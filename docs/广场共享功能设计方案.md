# 佛经阅读器 · 广场共享功能设计方案

> 状态：实施中（后端已定为腾讯云开发 CloudBase）
> 日期：2026-08-01
> 面向对象：单机本地版 → 多用户 + 笔记广场共享

---

## 1. 背景与现状

当前 App 是**纯本地单机版**：

- 笔记存储在 `SharedPreferences`（key=`notes`），字段只有 `id / title / content / updatedAt`（见 `lib/notes_page.dart:28`、`lib/note_edit_page.dart:46`）
- 用户资料（昵称、签名、头像）同样存本地（见 `lib/my_page.dart:45`）
- 无账号体系、无后端、无网络依赖

**本次变更目标**：

1. 引入账号体系（手机号 + 短信验证码登录）
2. 笔记从本地存储升级为云端存储，支持「分享到广场」
3. 新增「广场」：所有用户公开分享的笔记，人人可见
4. 保留离线可用体验（读经、看已缓存笔记不强制联网）

## 2. 总体架构

```
┌──────────────────────────────┐
│        Flutter App           │
│                              │
│  AuthService   ──登录/会话──┐ │
│  NotesService ──笔记 CRUD───┤ │
│  PlazaService ──广场拉取────┤ │
│  LocalCache(SharedPrefs)    │ │  离线缓存 + 待同步标记
└──────────────────────────────┘ │
                                 ▼
                        ┌──────────────────────┐
                        │   BaaS 后端(云端)     │
                        │  腾讯云开发 CloudBase │
                        │  认证(手机号+短信验证码)│
                        │  Note 数据表 + 权限    │
                        │  云函数(广场/点赞/举报) │
                        └──────────────────────┘
```

核心原则：

- **账号系统、数据存储、短信、云函数全部由 CloudBase 托管**，不自己搭服务器
- 认证走官方 `cloudbase_flutter` SDK；**所有数据操作（笔记/广场/点赞/评论/举报）统一走单个「api」云函数**，客户端不直接访问数据库，避免把数据库权限暴露给客户端
- 客户端保留本地缓存，**保存即同步**；网络失败时标记为「待同步」，下次联网重试

## 3. 技术选型

> 结论：**腾讯云开发 CloudBase（上海地域 `ap-shanghai`）**。
> 原 LeanCloud 国内版于 2026-01-12 停止新用户注册、2027-01-12 全面停服，已不可用，本方案改为 CloudBase。

| 维度 | 腾讯云开发 CloudBase | 自建后端（Node/Python + MySQL） |
|---|---|---|
| Flutter SDK | 官方 `cloudbase_flutter` SDK（活跃维护，支持认证/云函数） | 需自己写 HTTP 层 |
| 手机号验证码登录 | 内置，短信登录仅上海地域可用 | 需接短信商+自己写 |
| 数据库 | 文档型 / MySQL | 自选 |
| 云函数 | 支持 | 全部自己写 |
| 免费额度 | 体验版有免费额度 | 无 |
| 国内访问 | 上海等节点 | 需自备国内服务器 + 备案 |
| 上线速度 | ★★★★☆ | ★★☆☆☆ |
| 长期可控性 | 中 | 高 |

理由：
- CloudBase 官方 Flutter SDK（`cloudbase_flutter`）持续维护，认证（手机号+短信验证码）、云函数调用均可直接用
- 内置账户体系 + 短信验证码，几乎不用写登录逻辑
- 客户端**不直连数据库**，统一走「api」云函数（服务端用管理端权限操作数据库），天然规避越权风险
- 起步零成本，规模大了可升级付费档，也可迁移数据到自建后端

> 自建后端作为**规模增长后的远期路径**，现阶段不推荐。

## 4. 数据模型

### 4.1 用户（CloudBase 认证用户）

CloudBase 认证模块返回的用户对象（`User`），字段位于 `userMetadata`：

| 字段 | 类型 | 说明 |
|---|---|---|
| phone | String | 手机号，注册即登录（自动加 +86 前缀） |
| userMetadata.nickName | String | 昵称（默认「同修」） |
| userMetadata.avatarUrl | String | 头像（可选） |
| id | String | 用户 ID（云函数中作为作者标识） |

> 签名（tagline）CloudBase 不提供对应字段，保留本地存储，不同步云端。

### 4.2 笔记（新建 `notes` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| ownerUserId | String | 作者用户 ID（云函数用调用者身份写入，客户端不可伪造） |
| title | String | 标题 |
| content | String | 内容 |
| visibility | String | `private`（私密）/ `public`（公开到广场） |
| authorName | String | 作者昵称快照（冗余，避免联查） |
| likeCount | Number | 点赞数（冗余计数，避免实时聚合） |
| commentCount | Number | 评论数（冗余计数） |
| status | String | `normal` / `hidden`（违规隐藏） |
| createdAt / updatedAt | Number | 毫秒时间戳 |

**权限规则**（云函数内校验，客户端不直连数据库）：
- `private`：仅作者可读写
- `public`：所有人可读，仅作者可写
- `status = hidden`：查询层过滤，作者本人仍可见但广场不展示

### 4.3 点赞（新建 `noteLikes` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| noteId | String | 被赞笔记 id |
| userId | String | 点赞人（认证用户 id） |
| createdAt | Number | 时间戳 |

> 建唯一索引 `(noteId, userId)`，保证一人只能点一次赞。点赞数由云函数读改写更新 `notes.likeCount`。

### 4.4 举报（新建 `noteReports` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| noteId | String | 被举报笔记 id |
| userId | String | 举报人（认证用户 id） |
| reason | String | 举报原因 |
| createdAt | Number | 时间戳 |

> 同一人对同一笔记只能举报一次；举报数 ≥ 3 自动置 `status = hidden`。

### 4.5 评论（新建 `noteComments` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| noteId | String | 所属笔记 id |
| authorId | String | 评论人（认证用户 id） |
| authorName | String | 评论人昵称快照 |
| content | String | 评论内容（≤ 200 字） |
| createdAt | Number | 时间戳 |

> `notes.commentCount`（冗余计数），广场卡片展示评论数。

## 5. 云函数设计（CloudBase 云函数）

> 客户端**不直连数据库**。所有数据操作统一走**单个「api」云函数**（代码在 `cloudfunctions/api/`），通过入参 `action` 分发：
> `createNote / updateNote / deleteNote / getMyNotes / getPlazaNotes / getNoteById / getLikedNoteIds / toggleLike / reportNote / createComment / getComments / deleteComment / hideNote`

| action | 入参 | 出参 | 说明 |
|---|---|---|---|
| `createNote` | title, content, visibility, authorName | id | 创建笔记，校验登录态 |
| `updateNote` | id, title, content, visibility | id | 仅作者可改 |
| `deleteNote` | id | ok | 仅作者可删（级联删点赞/评论/举报） |
| `getMyNotes` | page, pageSize | notes[] | 我的笔记（含私密） |
| `getPlazaNotes` | page, pageSize, sort | notes[] + total + hasMore | 广场流：`visibility=public` 且 `status!=hidden` |
| `getNoteById` | id | note | 公开或作者本人可见 |
| `getLikedNoteIds` | - | ids[] | 当前用户点赞过的笔记 id（列表展示已赞态） |
| `toggleLike` | noteId | likeCount, liked | 读改写：查重→增删→更新计数 |
| `reportNote` | noteId, reason | total | 举报，达 3 次自动置 `hidden` |
| `createComment` | noteId, content, authorName | comment | 发表评论，校验登录态 |
| `getComments` | noteId, page, pageSize | comments[] | 按时间正序取评论 |
| `deleteComment` | commentId | ok | 仅评论作者或笔记作者可删 |
| `hideNote` | id | ok | 管理员用（控制台触发） |

> 云函数使用 `@cloudbase/js-sdk` v3（服务端自动带管理员凭证）操作数据库；调用者身份通过 `app.parseContext(context).environ.TCB_UUID` 获取，客户端无法伪造 `ownerUserId`，由云函数按 uid 做归属校验，降低越权风险。

### 5.1 部署步骤（用户手动执行）

1. 控制台 → 文档型数据库：新建集合 `notes` / `noteLikes` / `noteComments` / `noteReports`
2. 为 `noteLikes` 建**唯一索引** `(noteId, userId)`（索引管理 → 新建索引 → 两字段勾选「唯一」）
3. 控制台 → 云函数 → 新建函数，名称填 **`api`**，上传 `cloudfunctions/api/` 目录（index.js + package.json）
4. 依赖：`@cloudbase/js-sdk` 已声明在 package.json，控制台「依赖」页执行安装
5. 部署后测试调用一次 `createNote`，检查日志确认 `uid=` 非空（验证调用者身份解析正常）

### 6.2 修改文件

| 文件 | 改动 |

| `lib/main.dart` | 启动时恢复登录会话（`restoreSession`） |

| `lib/my_page.dart` | 头部显示登录状态；未登录显示登录入口；已登录显示昵称/退出登录；笔记行显示「广场」徽标；删除已分享笔记时同步删除云端 |
| `pubspec.yaml` | 新增依赖：`cloudbase_flutter`（官方 SDK，含认证与云函数） |

### 6.3 分享模型（已确认：只分享不迁移）

- 本地笔记**仍存本地**（现有 `notes` key 不变，零回归）
- 笔记编辑页新增「分享到广场」开关；开启保存时，通过「api」云函数把标题/内容发布到云端 `notes` 表（`visibility=public`）
- 本地笔记记录附加字段：`shared`（是否分享）、`cloudId`（云端笔记 id），用于同步状态与二次编辑同步
- 再次编辑已分享笔记并保存 → 更新云端副本；关闭开关保存 → 云端置为 `private`；删除已分享笔记 → 级联删除云端记录
- 用户可随时在广场看到自己分享的内容；广场展示作者昵称快照 `authorName`

### 6.4 离线策略（MVP 简化版）

- 本地笔记：完全本地读写，不依赖网络（与现状一致）
- 分享到广场：需在线；发布/更新/取消分享失败时提示用户稍后重试，不进入本地队列
- 广场：必须在线；断网显示「加载失败」空态 + 重试按钮

## 7. 广场功能设计

### 7.1 入口（已确认）

放在**首页「修学」页（`study_hub_page.dart`）的「功课打卡」区块下方**，新增一个「广场」入口卡片，点击进入 `PlazaPage`。不新增底部 Tab，保持现有三 Tab 结构不变。

### 7.2 广场页 UI

- 顶部 Tab 或排序：`最新` / `最热`（按 `likeCount`）
- 卡片：标题、内容摘要、作者昵称、发布时间、点赞数、评论数
- 交互：
  - 点击 → 笔记详情（只读）
  - 详情页内：点赞、评论列表、发表评论（登录后可发）、长按/更多 → 举报
  - 广场卡片点赞 → `toggleLike`（未登录先引导登录）
- 分页：下拉刷新 + 上滑加载更多（`scrollable_positioned_list` 已引入，可直接用）
- 内容：纯文本，不支持图片（已确认）

### 7.3 未登录体验

- 广场可**浏览**、看评论（公开内容）
- 点赞、发表评论、分享到广场、编辑自己的笔记需**登录**

## 8. 安全与合规（重要）

公开 UGC 内容在中国运营需注意：

1. **内容审核**：上线 UGC 前建议接入内容安全服务（腾讯云/阿里云文本审核）做自动过滤 + 用户举报人工复核
2. **用户协议 & 隐私政策**：App 内提供入口；说明手机号收集用途、内容发布规则
3. **违法内容处理**：举报达阈值自动隐藏，保留删除入口（云函数 `hideNote`）
4. **实名与短信**：手机号验证码本身即满足基本实名
5. **上架资质**：应用商店上架公开分享类 App 一般需要软著/相关资质，提前准备

> 说明：CloudBase 托管在国内节点，App 不需要单独 ICP 备案；但若日后自建后端并绑定独立域名，则必须走 ICP 备案流程。

## 10. 实施路线图

### 阶段 0：环境搭建与账号体系（1 天）
- 注册腾讯云开发 CloudBase，创建环境（**地域选上海 ap-shanghai**，短信登录仅上海可用）
- 控制台开通短信登录，配置短信签名/模板（验证码类）；生成 Publishable Key（环境 → API Key 配置）
- 将环境 ID / Publishable Key 填入 `lib/cloudbase_config.dart`
- Flutter 工程实现认证封装 + 登录页与会话保持（`auth_service.dart` / `login_page.dart`，已用 cloudbase_flutter SDK 重写）
- 本地昵称/签名迁移：昵称同步到认证用户，签名保留本地

### 阶段 1：笔记上云 + 分享开关（2-3 天）
- 在 CloudBase 控制台创建 `notes` / `noteLikes` / `noteComments` / `noteReports` 集合；为 `noteLikes` 建唯一索引 `(noteId, userId)`
- 部署「api」云函数（`cloudfunctions/api/` 目录：createNote/updateNote/deleteNote/getMyNotes/getPlazaNotes/toggleLike/reportNote/createComment/getComments/deleteComment 等 action）
- 笔记编辑页加「分享到广场」开关；本地笔记记录 `shared`/`cloudId` 状态
- 已在「我的」页显示「广场」徽标、删除级联清理云端

### 阶段 2：广场（2-3 天）
- `plaza_page.dart`（最新/最热排序、分页、点赞、进详情）、`note_detail_page.dart`（点赞 + 评论 + 举报）
- 「修学」页「功课打卡」区块下方「广场」入口卡片
- 未登录引导登录、广场空态/错误态

### 阶段 3：合规与打磨（1-2 天）
- 接入文本内容安全（自动过滤）
- 用户协议 / 隐私政策页
- 管理端隐藏违规内容入口

> 总计约 **1 周**可完成 MVP 上线。每个阶段可独立验收，先做阶段 0+1 保证老功能不回归。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 云端数据误删/丢失 | 中 | 笔记删除走云函数校验；CloudBase 控制台开启数据备份 |
| 断网时分享失败 | 中 | 本地笔记不受影响；分享操作失败提示重试，不入队列 |
| 免费额度不够 | 中 | 起步规模可控；超限前切换到付费档 |
| 内容违规被举报/监管 | 高 | 自动审核 + 举报 + 隐藏/删除机制必须上线 |
| 越权访问他人私密笔记 | 高 | 全部走「api」云函数 + 服务端按 uid 归属校验，客户端不直接暴露数据权限 |

## 12. 已确认决策汇总

| 问题 | 决策 |
|---|---|
| 数据迁移 | 不需要。当前 App 刚开发、只有自己使用，无老用户数据 |
| 笔记云化范围 | **只分享不迁移**：本地笔记仍存本地，分享开关发布/同步云端副本 |
| 广场入口 | 首页「修学」页「功课打卡」区块下方入口卡片，不加新 Tab |
| 互动范围 | MVP 含点赞 + 举报 + **评论** |
| 笔记图片 | 不支持，纯文本（含广场内容） |
| 昵称策略 | 手机号注册后默认「同修+尾号」，用户可自行修改 |
| 数据归属 | 托管在腾讯云开发 CloudBase（MVP 阶段），方案保留日后自建后端的迁移退路 |
