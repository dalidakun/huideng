# 菩提空间帖子分享 · 微信链接卡片方案

> 状态：已上线（2026-10-24，环境 randeng-d8gs968w22a3d98e8 / 域名 aibuilder.top）
> 相关代码：`lib/post_share.dart`、`cloudfunctions/api/post_page.js`、
> `cloudfunctions/api/index.js`、`site/post.html`（旧版，保留给老链接）

---

## 1. 目标

帖子右上角三点 → 「分享笔记」→ 分享到微信等第三方。希望微信聊天里显示成
「左侧缩略图 + 标题 + 摘要」的链接卡片，点卡片就在微信内置浏览器里打开这条帖子。

## 2. 为什么必须服务端渲染

微信用抓取器请求一次链接来生成卡片，**不执行 JavaScript**，只读首字节 HTML 里的
`og:title` / `og:description` / `og:image`。原来的 `site/post.html?id=<id>` 是纯前端页：
浏览器能靠 fetch 填出正文，但抓取器看到的只有站点级的通用标题与封面。

所以新分享页由 `api` 云函数现场渲染：帖子正文、作者、统计与 og 标签一起写进首字节
HTML。抓取器拿到卡片信息，真实读者拿到的也是同一份静态 HTML（不依赖 JS，
JS 只用来打一个阅读数信标）。

## 3. 链接形态

```
https://aibuilder.top/post/<id>.html
```

`<id>` 有两种：

- **帖子 id**（`notes._id`）：菩提空间每条帖子右上角三点 →「分享笔记」；
- **祈福项目 id**（`blessingProjects._id`）：祈福详情页右上角分享图标。

云函数按 id 先查 `notes`、查不到再查 `blessingProjects`，所以两种内容共用一个地址形态
（不用再加一条网关路由）。

- `/post` 这条路径由 CloudBase [HTTP 网关] 路由到云函数 `api`（静态托管只占 `/`），
  路径前缀匹配，所以 `/post/xxx.html`、`/post/xxx` 都会进来；
- 旧链接 `/post.html?id=<id>` 仍然可用：静态托管上还有这份页面（网关前缀 `/post`
  不匹配 `/post.html`）。已发出的旧分享不会失效，只是卡片是发的时候抓的，改不了。

## 4. 部署

### 4.1 云函数代码（每次改分享页都要做）

```bash
cd cloudfunctions/api
tcb fn code update api -e randeng-d8gs968w22a3d98e8
```

**必须在 `cloudfunctions/api` 目录里执行。** 在仓库根目录用 `--dir cloudfunctions/api`
时，CLI 仍会把整个仓库（含 `build/` 里几个 GB 的构建产物）打进包里，表现是
「COS 上传超时（60秒）」或 `EBUSY / ENOENT` 指向 `build/app/intermediates/...`。
用 `tcb fn code update`（而不是 `tcb fn deploy`）的好处：只换代码，不动函数的环境变量
（DEEPSEEK_API_KEY / GITHUB_TOKEN / TCB_CUSTOM_LOGIN_CREDENTIALS）。

### 4.2 HTTP 网关路由（只需配一次，已配好）

```bash
tcb routes add -e randeng-d8gs968w22a3d98e8 --data ^
  '{"domain":"aibuilder.top","routes":[{"path":"/post","upstreamResourceType":"SCF","upstreamResourceName":"api","enablePathTransmission":true}]}'

tcb routes list -e randeng-d8gs968w22a3d98e8
```

`tcb routes list` 里应能看到：

| 域名 | 路由 | 资源类型 | 资源对象 | 路径透传 |
| --- | --- | --- | --- | --- |
| aibuilder.top | `/` | STATIC_STORE | staticstore | 开启 |
| aibuilder.top | `/post` | SCF | api | **开启** |

**路径透传（enablePathTransmission）必须开**，否则函数收到的是剥掉前缀的路径，
拿不到 `/post/<id>.html` 里的 id，页面会报「链接不完整」。

也可以控制台配：云开发控制台 → HTTP 网关 → 路由管理 → 新建，
关联资源类型选「云函数」→ `api`，触发路径 `/post`，域名 `aibuilder.top`，
然后编辑该路由打开「路径透传」。

### 4.3 站点静态资源（只有改了 `site/` 才需要）

```bash
python tools/update_site.py
```

分享页的图标、封面图 `assets/share-cover.png` 都来自静态托管，函数里写的是绝对地址
`https://aibuilder.top/assets/...`，不再走相对路径，所以页面放在 `/post/` 下也不会取错。

## 5. 验证

```bash
# 1) 返回类型与上游
curl -sI https://aibuilder.top/post/<帖子id>.html
#   期望：HTTP/1.1 200、content-type: text/html; charset=utf-8、
#         x-cloudbase-upstream-type: Tencent-SCF（不是 Tencent-COS）

# 2) og 标签
curl -s https://aibuilder.top/post/<帖子id>.html | grep 'og:'

# 3) 不存在的帖子 → 404 的友好页；私密/隐藏帖同样当不存在
curl -s -o /dev/null -w '%{http_code}\n' https://aibuilder.top/post/not-exist.html

# 4) 图片公网可访问（微信抓封面用）
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' https://aibuilder.top/assets/share-cover.png
```

真机验收：微信里发给自己 → 应显示链接卡片；点开 → 微信内置浏览器打开同一页，
标题栏是帖子标题，正文完整。

**验证时的两个坑**：

1. 响应带 `Cache-Control: public, max-age=60, s-maxage=300`，改完再测同一个 URL 可能还是
   旧内容。验证时换个路径最稳（`/post/<id>.html` 与 `/post/<id>` 是两个缓存键），
   或者等 5 分钟。
2. `tcb fn code update` 成功后还有几十秒的版本切换时间，这段时间里可能仍返回旧代码。

## 6. 卡片内容规则

| 帖子类型 | 卡片标题 og:title | 卡片摘要 og:description |
| --- | --- | --- |
| 有标题 | `<标题> · 菩提空间` | 正文首段（≤88 字） |
| 无标题 | 正文前 20 字 | 正文首段；很短时用结构化信息或站点一句话 |
| 为众祈福（帖子） | `为<回向对象>祈福` | 回向文（没有则回向对象/备注） |
| 为众祈福（项目页） | 模板名，如 `为父母及家人祈福` | 回向文 |
| 人天利益 | `人天利益 · <佛号/神咒>` | 备注，没有则经文段落 |
| 回复/引用帖 | 同上 | 一句话回复后面会补上被引用的原帖 |

封面固定为 `https://aibuilder.top/assets/share-cover.png`（640×640，米色底 + **圆形**
鼎 logo，供微信卡片左侧缩略图使用）。
正文明细（结构化卡片、引用块、阅读/点赞/评论）与 `site/post.html` 的渲染规则逐条对齐，
改一处要同步另一处。

页面上的两个按钮——顶部「打开 App」和底部「打开燃灯，查看更多笔记」——都指向官网
首页 `https://aibuilder.top/`（首页自带下载入口），不再直接跳 `download.html`。
旧的 `?id=` 静态页已同步改成同样的目标。

App 侧入口（都调 `SharePlus`，系统分享面板从底部弹出，选微信即发链接）：

| 入口 | 代码 | 分享的 id |
| --- | --- | --- |
| 菩提空间帖子三点 →「分享笔记」 | `lib/note_detail_page.dart`、`lib/post_rich_content.dart` | 帖子 id |
| 祈福详情页右上角三点 →「分享到……」 | `lib/blessing_page.dart` 的 `_shareToPlatforms` | 祈福项目 id |
| 祈福详情页右上角三点 →「转发到菩提空间」 | `lib/blessing_page.dart` 的 `_share` | 在广场里生成一条祈福帖（需登录） |

三点菜单里「分享到……」= 系统分享面板（微信等），「转发到菩提空间」= 在广场生成祈福帖；
发起人还能看到「编辑 / 删除」。菜单项只用文字、不带图标，免得图标与文字颜色不统一。
主页（学习中心）祈福卡片上的分享图标已移除，分享入口统一放在祈福详情页。

## 7. 阅读数

分享页里有一段 `fetch("/post/<id>.html?view=1")`：只有执行 JS 的真实浏览器会打这个
请求，函数收到 `view=1` 就把 `viewCount` +1 并返回 204。抓取器不跑 JS，不会虚增阅读量。
旧静态页仍走 `incView` 接口，行为不变。

## 8. 局限（微信侧决定，不是代码能控的）

1. 卡片样式由微信决定：是「链接卡片」，不是公众号那种大图文卡。
2. 每帖用同一张固定封面（圆形 logo）。微信只按 og:image 取缩略图，做不到按帖子
   换图；真要「每帖不同图」得在服务端按帖子生成图片，成本高很多。
3. 分享文案**只放链接**。微信只对纯链接消息去抓 og 渲染卡片；掺了文字就退化成普通
   文本气泡（链接仍可点，但没有缩略图卡片）。摘要不用写进文案——它就在卡片里。
4. 卡片抓取结果由微信侧缓存，改标题后短时间内可能还是旧卡片；换封面图同理。
   第一次抓取时页面如果是 4xx/5xx（比如路由还没配好），微信就只显示一串纯链接，
   重新发一条新链接才会重新抓。
5. 域名需备案 + HTTPS + 公网可访问（aibuilder.top 已满足）。若被判定诱导分享，
   微信会拦截该域名下的链接——这与实现方式无关。

## 9. 排障

| 现象 | 排查 |
| --- | --- |
| `/post/xxx.html` 404，日志无调用 | 网关路由没配或域名不对：`tcb routes list -e <env>` |
| 页面提示「链接不完整」 | 路由的「路径透传」没开，函数拿不到完整路径 |
| 卡片只显示站点名 | 抓的是旧静态页（老链接 `/post.html?id=`），或页面是纯前端渲染 |
| 改完代码没生效 | 函数是否部署成功（`tcb fn detail api` 看修改时间）；再换个 URL 路径试（CDN 缓存 5 分钟） |
| 卡片没有缩略图 | `curl -I https://aibuilder.top/assets/share-cover.png` 是否 200；防盗链是否拦了 referer |
