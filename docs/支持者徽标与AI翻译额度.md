# 订阅服务 + AI 翻译额度（实现说明）

> 状态：客户端与管理端已完成，云函数需重新部署。
> 定价：免费档 1000 次翻译；199 元一次性，无限翻译 + 附赠支持者徽标（长期有效）。
> 收款：微信 / 支付宝个人收款码，**人工核对备注后开通**，不再自动核销交易单号。

---

## 1. 产品规则

| 项目 | 规则 |
| --- | --- |
| 免费额度 | 每个账号 **1000 次**（按“不同段落”计，同一段重复打开不扣） |
| 订阅价格 | **199 元一次性**：无限翻译 + 附赠支持者徽标 |
| 订阅有效期 | 长期有效（服务端按 100 年写入，等价永久） |
| 收款方式 | 微信 / 支付宝个人收款码（两个码并排展示，任选其一） |
| 开通方式 | 用户付款时在**备注**填写自己的账户名、手机号或用户ID；管理员在 App 内核对后手动开通 |
| 开通权限 | **仅第一管理员 `@randeng`** 可手动开通；其他管理员看不到订阅服务区块 |
| 取消订阅 | **不支持**（开通后不可取消） |
| 单号校验 | **不再使用**：旧 `submitBadgeTxn` 已停用，统一返回人工开通提示 |
| 人工介入 | 必需（管理员按账户名 / 手机号 / 用户ID 查找用户并开通） |

**重要**：个人收款码没有支付回调，系统无法验证金额与到账。  
现在的流程是「付款备注 → 管理员人工核对 → 手动开通」，不存在“输入单号自动开通”的漏洞。  
徽标文案必须写“付费支持 / 附赠”，不能暗示实名认证。

---

## 2. 用户流程

1. 侧边栏（头像旁）→「订阅服务」；
2. 页面顶部展示 AI 翻译权益与 ¥199 价格，下方展示「我的账户信息」（账户名 / 手机号 / 用户ID，均可复制）；
3. 微信或支付宝扫码付款 199，付款时在备注里填写账户名（@xxx）、手机号或用户ID；
4. 管理员收到款项、看到备注后，在 App 内手动开通；
5. 用户回到「订阅服务」页即可看到「已开通」，AI 翻译变为无限次；底部「消息」页会收到一条「恭喜你获得无限翻译和认证徽标」系统信息；
6. 未开通且免费额度用完时，翻译弹层 / 段落翻译页会**直接弹窗**提示开通（不再显示剩余次数）。

## 3. 数据表

| 集合 | 说明 |
| --- | --- |
| `supporterBadges` | 一个用户一条：`uid / plan / priceFen / channel / txnNo / startAt / expireAt`（人工开通时 `channel=manual`） |
| `aiQuota` | 一个用户一条：`freeLimit=1000 / freeUsed / unlimited / unlimitedUntil` |
| `aiUses` | 段落核销：`_id = sha1(uid + "|" + 段落哈希)`，同一段只计一次 |
| `userAccounts` | 账号名 / 手机号 / uid 对照，管理员按账户名或手机号查找用户 |
| `admins` | 管理员名单，`adminSetSubscription` 会校验 |
| `featureBans` | `_id = uid`；存在即禁止该账号使用 AI / 订阅 |
| `featureAppeals` | 被限制用户的申诉记录 |

`badgeClaims`、`userVerifications` 为旧版遗留集合，不再写入（清理接口仍会删除旧记录）。

## 4. 服务端改动（`cloudfunctions/api/index.js`）

| action | 作用 |
| --- | --- |
| `submitBadgeTxn` | **已停用**，返回人工开通提示（兼容旧客户端） |
| `adminSetSubscription` | 仅第一管理员 `@randeng`：按账号名 / 手机号 / 用户ID 开通（不可取消），并向「消息」页写一条开通信息 |
| `reportMyPhone` | 客户端登录后上报手机号，写入 `userAccounts.phone` |
| `getMyVerification` | 返回徽标是否有效、到期时间（旧客户端兼容） |
| `getMyAiQuota` | 返回免费 / 付费 / 无限额度快照 |
| `aiTranslate` | 翻译前按“用户 + 段落”核销；成功返回 `quota` |
| `getParagraphTranslation` | 同样核销（保留给旧调用方） |
| `adminResetBadges` | 清空所有徽标，并重置管理员自己的额度（测试用） |
| `verifyIdentity` | **已停用**，返回“实名认证已停用” |

所有作者徽标（笔记 / 评论 / 通知 / 资料）读 `supporterBadges` 且 `expireAt > now`。

### 部署

1. 上传 `cloudfunctions/api` 并部署；
2. 首次调用会自动建集合；若云环境禁止自动建表，手动创建：
   `supporterBadges`、`aiQuota`、`aiUses`、`userAccounts`；
3. 不需要额外索引（`_id` 唯一性已足够）；
4. 确保至少一位管理员已在 `admins` 集合登记。

## 6. 测试

### 本地逻辑测试（无需云环境）

```bash
node tools/test-badge-api.js
```

覆盖：旧单号入口已停用、1000 次免费上限、同段不重复扣、第一管理员按账户名开通、非第一管理员无权限、消息页开通信息、不可取消。

### 真机测试

1. 用普通账号打开「订阅服务」，确认账户名 / 手机号 / 用户ID 显示与复制正常；
2. 免费额度用完后点 AI 翻译，应直接弹窗（而不是顶部剩余次数）；
3. 用 `@randeng` 登录，在「关于我们 → 管理员 → 订阅服务」输入该用户账户名 / 手机号 / 用户ID → 点「开通」；
4. 用户底部「消息」页应出现「恭喜你获得无限翻译和认证徽标」信息；回到订阅页显示「已开通」，AI 翻译不再扣次数；
5. 用其他管理员登录，「关于我们 → 管理员」不应出现订阅服务区块。

## 7. 管理员操作

- **手动开通**（仅 `@randeng`）：用户付款备注里的账户名 / 手机号 / 用户ID → 「关于我们 → 管理员 → 订阅服务」输入 → 点「开通」；其他管理员看不到该区块；
- **取消订阅**：不支持；开通后不可取消；
- **清空测试数据**：`adminResetBadges` 接口仍保留（清空全部徽标），客户端不提供批量清空入口；
- **开通提示**：开通成功时向用户 `activities` 写入一条 `subscription` 系统信息，显示在底部「消息」页并计入未读，点击进入订阅页；
- **限制用户**：在任意用户主页 / 帖子长按 →「限制 / 解除该用户 AI 使用」；
- **查看申诉**：云开发控制台看 `featureAppeals`，处理后手动解除限制。

---

## 8. 已知边界（必须接受）

- 人工开通依赖管理员及时核对备注；备注缺失时，用户可按订阅页提示到「设置 → 关于我们 → 反馈问题」补填备注；
- 无法自动核对金额（例如付 0.01 元），需管理员按备注与到账金额人工判断；
- 个人收款码用于远程经营收款，存在微信 / 支付宝风控与限额风险；
- 徽标是“支持者”标识，不是实名认证；UI 已按此文案处理。

如果以后要“自动验证”，只能接微信支付 / 支付宝商户号（需企业或个体户）。
